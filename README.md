# 🔥 Prosper Heat

**A live, gamified lead-distribution engine for sales teams — built on iMessage, Redis, and LLM-classified rep responses.**

> Built by Craig Stratton + Hanna (Claude Sonnet 4.6) in a single afternoon to solve a real problem: getting hand-picked closers to actually work fresh inbound leads with speed, accountability, and a real prize on the line.

This is the working, open-source codebase. Everything is here — the daemons, the prompts, the schemas, the LLM calls. Fork it, run it, tweak it, push back. It's intentionally simple. macOS-only today (because iMessage is the rail), but the architecture maps to Twilio / Telnyx / GHL for any rail you want.

---

## Why this exists

Most lead distribution tools route leads but don't drive behavior. Prosper Heat is the opposite — the routing is the easy part. The hard part is **getting reps to actually call AND text inside 5 minutes**, **acknowledge what they did**, and **stay hungry across a full session**.

The trick: turn the daily session into a contest with a real cash prize, instant point feedback after every action, and an engagement multiplier so the rep who works 10 leads has a way bigger payout per SET than the rep who works 2.

**Point system:**

| Action | Points |
|---|---|
| CALL the homeowner | +2 |
| TEXT the homeowner | +1 |
| SET (lock the appointment) | +5 × leads_worked_today |
| MISS (released, no live answer) | 0 (no penalty) |

The set multiplier is the engagement lever. SET on your 1st lead = +5. SET on your 8th lead = +40. Reps lean in because every set they lock pays bigger as they stack volume.

### Daemons (all macOS launchd jobs)

| Daemon | Cadence | Purpose |
|---|---|---|
| `io.prosper.heat-engine` | every 30s | Read new inbounds, classify, update Redis, auto-serve next lead |
| `io.prosper.lead-timer` | every 60s | Fire T+5 reminder + T+15 reassign on active leads (tunable) |
| `io.prosper.heat-hourly` | :00 + :30 | Write digest snapshot to `~/ClaudeCodexBridge/prosper-heat-digest-latest.txt` |
| `io.prosper.contest-winner` | 9:00 PM | Compute leaderboard, write winner announcement |
| `io.prosper.imessage-responder` | live | Sonnet-drafted natural-language replies for non-contest messages |

### Classification strategy

**Tier 1 — strict regex** (microsecond, free):
- `^CALLED|^CALL|^TEXTED|^TEXT|^SET|^MISS|^NEXT|^READY|^YES|^NO|^PAUSE|^GO`
- Catches reps who follow the protocol exactly.

**Tier 2 — LLM fallback** (≈2 seconds, ~$0.001 per call):
- Strict regex misses → call `claude-haiku-4-5-20251001` via local CPAMC gateway with a tight system prompt that returns JSON like `{"verbs": ["CALL","TEXT","MISS"], "reason": "..."}`.
- Handles natural language: *"Joyce and David I called and texted, please read my notes"* → `["CALL","TEXT","CALL","TEXT","MISS","MISS"]` (or however the LLM interprets it).
- Generous interpretation by design — reps shouldn't have to memorize syntax.

### Lead pool

`prosper-heat-lead-pool.json` is a JSON file generated by `helpers/prosper-heat-extract-leads.py` which:
1. Reads chat.db for all `New Solar Exclusive Lead:` messages
2. Parses name / phone / email / address / bill / utility / shade
3. Dedupes by phone number (most recent dupe wins per rep)
4. Writes a single pool file the engine pops from

## Bootstrap

### Prerequisites
- macOS (this codebase uses iMessage as the rail)
- bun 1.3+ at `~/.local/bin/bun` (FDA granted)
- python 3.9+
- redis-server running locally (we use a small wrapper `redis-prosper` that loads env from `~/.config/prosper/prosper.env`)
- A local OpenAI-compatible LLM gateway at `http://127.0.0.1:8317/v1/chat/completions` (we use CPAMC — claude-proxy-anthropic-multi-claude — with per-agent Bearer tokens; any OpenAI-compatible gateway works)
- A Solar Exclusive Leads (or equivalent) iMessage feed sender for the lead pool source

### One-time setup
```bash
# Grant Full Disk Access to bun (System Settings → Privacy & Security → Full Disk Access → +)
# This lets bun:sqlite read chat.db.

# Install daemons
cp launchd/*.plist ~/Library/LaunchAgents/

# Bootstrap each daemon
for plist in ~/Library/LaunchAgents/io.prosper.{heat-engine,lead-timer,heat-hourly,contest-winner}.plist; do
  launchctl bootstrap gui/$(id -u) "$plist"
done

# Generate the lead pool
python3 helpers/prosper-heat-extract-leads.py

# Init Redis state for your reps (edit reps list in heat-engine.py first)
# See bin/prosper-heat-engine.py REP_NAMES dict
```

### Send opt-in to your reps

Use any iMessage sender (we use the `Read_and_Send_iMessages` MCP via Claude). The opt-in template is in `docs/opt-in-templates.md`:

- **1A — Full "you got tapped" (top-closer framing):** identity-driven, hand-picked language
- **1B — Short tight version:** SMS-style, scannable
- **1D — Additive framing (Monty variant):** for reps who already have a full plate — "this is on top of what you're already running"

Each opt-in includes the YES/NO/PAUSE/GO/CONTACTED/MISS protocol so reps know the syntax upfront.

## What's working

✅ **Lead distribution end-to-end:** Pool of 83 unique homeowners → auto-assigned to whichever active rep is at the top of the leaderboard (80/20 lean — hungry reps eat first).

✅ **Point tally:** CALL +2, TEXT +1, SET +5×leads_worked. Live in Redis, ack message in <3 seconds per rep reply.

✅ **LLM fallback classification:** When a rep says natural language ("I called and texted Joyce, no answer"), Haiku 4.5 parses it into the action list.

✅ **Auto-next on MISS/SET:** Rep doesn't need to type NEXT after a MISS or SET — engine pops the next lead from the pool automatically.

✅ **T+5 reminder cadence:** Lead-timer fires a "clock check" reminder when a rep has been silent on a lead for 5 minutes.

✅ **Hourly digest:** Written to a file the operator (or another AI agent) can surface in chat. No Telegram / no Slack / no external system dependency.

## What's broken / what's next

🚧 **Lead-timer T+15 reassign aggressive on natural-language replies:** Disabled overnight because it was timing out reps who replied in natural language faster than the strict-keyword window allowed. The LLM fallback should fix this — re-enable after the new engine has been live for an hour.

🚧 **No rep-to-rep dispatch yet:** A reassigned lead currently goes back to the pool. Should next-priority active rep pick it up automatically. Easy fix in `assign_next_lead()`.

🚧 **No keyword router in the responder daemon:** The iMessage responder (Sonnet-pinned natural language assistant) still answers contest-verb replies sometimes — those should be deferred to heat-engine. Add the regex to blocklist.ts SPAMMY_BODY_PATTERNS.

🚧 **No mobile push for Craig:** Operator currently relies on Cowork chat for digest visibility. Future: simple HTML dashboard at `localhost:8080` that polls Redis.

🚧 **Lead-quality scoring:** Right now every lead is treated equal. Future: assign higher base points for $400+/mo bills, no-shade roofs, etc.

🚧 **Rep-tone personalization:** `rep_mapping.json` already has tone signatures per rep (Cole = numbers-first dry, Garett = real-quick direct, Jeff = plainspoken no-fluff). Lead packets could be personalized to each rep's voice. Future work.

🚧 **Multi-source lead intake:** Currently only Solar Exclusive feed via iMessage. Extend to GHL webhooks, Twilio numbers, Calendly bookings, web form submissions.

🚧 **Cross-day persistence:** Daily counters reset at midnight ET. Need a midnight job that snapshots the day's leaderboard before zero-ing the `*_today` fields.
